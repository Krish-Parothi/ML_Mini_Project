Viva Voce Defense & Justification Deck

Curated mathematical and methodological justifications for academic examiners.

QUESTION 1 • BENCHMARK SELECTION

Why choose the PhiUSIIL dataset over legacy repositories?

Justification: Legacy phishing datasets exhibit severe structural flaws: (1) small sample sizes (<10k rows) prone to overfitting, (2) synthetic imbalances, and (3) lexical strings only. PhiUSIIL (235,795 verified URLs) provides 54 multi-dimensional attributes spanning lexical composition, character continuation rate, domain entropy, external references, and DOM traits, reflecting real-world zero-day attack tactics.

QUESTION 2 • DATA LEAKAGE PREVENTION

How was data leakage strictly eliminated during preprocessing?

Justification: Leakage occurs when test set statistics contaminate training. We enforced strict pipeline boundaries: (1) Identifier/free-text fields (FILENAME, URL, Domain, Title) were purged prior to feature creation, (2) Stratified train-val-test splitting (65% train, 15% val, 20% test) was performed before any scaling, and (3) The StandardScaler was fitted strictly on the training partition and transformed on validation and test sets.

QUESTION 3 • METRIC JUSTIFICATION

Why is Recall prioritized over Accuracy in threat detection?

Justification: In cybersecurity threat mitigation, error costs are highly asymmetric. A False Negative (classifying a phishing link as legitimate) leads to credential theft, account takeover, and data compromise. A False Positive merely generates a cautionary user confirmation prompt. Therefore, Recall for the phishing threat class must approach 100% to guarantee threat interception.

QUESTION 4 • 100% ACCURACY & SEPARABILITY

Is the near-100% accuracy an indicator of overfitting?

Justification: No. In classical overfitting, test performance drops significantly below training performance. Here, 100% accuracy was sustained over 12,000 unseen held-out test URLs, and even a regularized linear Logistic Regression achieved 99.98% accuracy. This demonstrates strong feature separability created by combining page complexity metrics (LineOfCode, NoOfExternalRef) and lexical metrics (URLSimilarityIndex) in the PhiUSIIL benchmark.

QUESTION 5 • ARCHITECTURE SELECTION

Why did LightGBM and XGBoost outperform Deep Learning on this task?

Justification: Tabular cybersecurity data features non-linear orthogonal decision boundaries and non-uniform distributions. Gradient Boosted Decision Trees (GBDT) partition feature space hierarchically without requiring manifold continuity, manage heterogeneous feature scales without heavy normalization, and run inference in 0.006 ms/sample, compared to deep neural networks which require massive parameter overhead and GPU inference.

QUESTION 6 • LATENCY & DEPLOYMENT

How does this architecture achieve cross-platform accessibility and line-rate speed?

Justification: The backend is served via an asynchronous FastAPI microservice hosting serialized .joblib models with an in-memory footprint of ~50 MB. Single URL feature extraction executes in under 0.5 ms. The REST API is platform-agnostic, making it a drop-in component for browser extensions (Chrome/Firefox), mail transfer agents (MTAs), and web gateways.
